# Sprint4 支付退款与库存锁定冻结规则 V1.8.1

来源：项目冻结执行指令（2026-08-15）。本文件为 Sprint4 唯一开发依据。

## 目标与边界

实现 `payment_record`、`refund_record`、微信支付基础接入、Mock 支付、支付回调、支付与退款幂等、库存锁定/确认/释放、超时取消、支付退款消息及前后台基础页面与测试。禁止提前实现分账、积分、复杂优惠券、配送、部分退款、供应链业务。

## 冻结数据模型

- `payment_record`：平台 `payment_no` 唯一；关联订单、用户、微信渠道、`mini_program` 交易类型、订单应付金额快照、渠道流水与预支付 ID、脱敏原始响应、支付状态与时间。状态仅可为 `created`、`pending`、`success`、`failed`、`closed`、`refunding`、`refunded`。
- `refund_record`：平台 `refund_no` 唯一；关联支付/订单/用户；仅整单全额退款；保存退款金额、原因、渠道退款单号、脱敏响应和状态。状态仅可为 `created`、`processing`、`success`、`failed`、`closed`。
- 订单支付状态：`unpaid`、`paid`、`refunding`、`refunded`、`failed`。支付成功订单状态为 `paid`；退款成功订单状态为 `cancelled`。

## 核心业务规则

1. 支付金额一律从 `orders.payable_amount` 读取，禁止信任前端金额。
2. 一个订单可保存多次支付尝试，但同一时刻只允许一个有效流程；已成功支付禁止再次创建支付。
3. 创建待支付订单时，事务内使用 PostgreSQL 行锁校验并执行：`available_stock -= quantity`、`locked_stock += quantity`、创建订单/明细、处理购物车；任一步失败必须回滚。
4. 支付成功只执行 `locked_stock -= quantity`，不得再次扣减 `available_stock`。
5. 待支付取消、超时取消必须在事务中执行 `locked_stock -= quantity`、`available_stock += quantity`，且同一订单只释放一次。
6. 超时时间使用 `ORDER_PAYMENT_TIMEOUT_MINUTES`，默认 30 分钟；每分钟扫描，超时订单取消原因为 `payment_timeout`。
7. 支付成功回调必须验签、解密、校验商户/订单/金额/支付记录，并按 `payment_no` 或渠道交易号幂等；重复成功回调不得重复扣库存、发消息或更新状态。
8. 若超时取消和可信支付回调竞态，必须以数据库事务状态保护库存；已取消订单收到真实支付成功时记录异常事件并进入人工处理/退款流程，不得静默吞掉。
9. 后台退款仅授权财务/退款权限操作；本期整单全额退款，退款金额恒等于 `paid_amount`；退款成功后未履约订单恢复库存一次。
10. 禁止记录私钥、API Key、完整证书或敏感支付凭据。

## API 冻结

- `POST /api/v1/app/orders/:orderId/pay`
- `GET /api/v1/app/orders/:orderId/payment-status`
- `POST /api/v1/payment/wechat/notify`
- `POST /api/v1/payment/wechat/refund-notify`
- `GET /api/v1/admin/payments`
- `GET /api/v1/admin/payments/:id`
- `GET /api/v1/admin/refunds`
- `GET /api/v1/admin/refunds/:id`
- `POST /api/v1/admin/orders/:orderId/refund`

## Provider 与安全要求

业务层依赖 `PaymentProvider`；开发/测试环境允许完整 Mock Provider（成功、失败、重复/延迟回调、退款成功/失败），生产环境必须使用微信支付 API v3 Provider。微信 App ID、商户号、API v3 Key、证书序列号、私钥与回调地址只从环境变量读取。真实微信调用、签名、证书、验签与解密以实施当日官方 API v3 文档为准。

## 验收门禁

必须覆盖创建支付、越权/重复支付、金额篡改、支付与退款回调幂等、签名与金额错误、库存锁定/释放/确认、并发库存不足、超时/支付竞态、全额退款/超额拒绝、消息生成和重启后支付退款记录保留。完成后通过 `typecheck`、`build`、Sprint1-4 回归与 Mock 支付全链路。真实微信凭据不足时允许以“代码完成 + Mock 验证通过 + 真实微信联调待配置”关闭工程开发部分。
