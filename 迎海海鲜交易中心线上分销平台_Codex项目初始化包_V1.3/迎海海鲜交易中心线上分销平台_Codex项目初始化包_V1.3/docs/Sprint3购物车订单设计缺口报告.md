## 二、当前不可直接开发原因

按照项目冻结规则，涉及数据库、API、页面流程和业务状态机的功能，不允许 Codex 自行补充设计。

Sprint3 属于交易链路核心模块，存在较高业务风险，当前文档不足以支持开发。

## 三、缺失设计项

进入 Sprint3 开发前，至少需要冻结以下内容：

1. 购物车数据库设计
   - `cart` 或 `cart_item` 表是否拆分
   - 用户、商品、SKU、数量字段
   - 是否支持失效商品
   - 是否支持勾选状态

2. 订单数据库设计
   - 订单主表字段
   - 订单明细表字段
   - 收货地址快照字段
   - 商品价格快照字段
   - 店铺信息快照字段

3. 订单状态机
   - 待付款
   - 待发货
   - 待收货
   - 已完成
   - 已取消
   - 售后/退款是否本期包含
   - 状态流转限制

4. 库存处理规则
   - 加入购物车是否校验库存
   - 下单是否锁库存
   - 未支付订单超时是否释放库存
   - Sprint3 是否只做基础下单，不做真实库存锁定

5. 用户端 API
   - 购物车列表
   - 加入购物车
   - 修改数量
   - 删除购物车项
   - 勾选购物车项
   - 创建订单
   - 订单列表
   - 订单详情
   - 取消订单

6. 后台 API
   - 订单列表
   - 订单详情
   - 修改订单状态
   - 发货
   - 备注
   - 导出是否本期包含

7. 页面设计
   - 小程序购物车页
   - 确认订单页
   - 订单列表页
   - 订单详情页
   - 后台订单管理页
   - 手机 H5 后台是否参与订单处理

8. 支付边界
   - Sprint3 是否只生成待支付订单
   - 支付是否进入 Sprint4
   - 是否需要支付单表预留

## 四、暂停结论

Sprint3 当前不满足“设计冻结后开发”的条件。

结论：

- 不创建数据库 Migration
- 不创建订单/购物车 API
- 不创建交易业务页面
- 不修改库存扣减逻辑

等待补充 Sprint3 冻结设计文档后再继续。
