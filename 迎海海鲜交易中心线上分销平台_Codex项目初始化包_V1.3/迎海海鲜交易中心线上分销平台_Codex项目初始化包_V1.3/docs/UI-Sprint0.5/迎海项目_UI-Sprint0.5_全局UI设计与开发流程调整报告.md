# 迎海项目 UI-Sprint 0.5 全局 UI 设计与开发流程调整报告

状态：待产品负责人 UI Gate 评审  
范围：微信小程序用户端、PC/iPad H5 管理后台、手机 H5 工作台  
原则：未经过 UI Gate 冻结的新业务页面，不进入正式前端开发。

## 1. 流程调整结论

当前开发流程由“设计文档 → 后端/数据库/API → 前端开发 → 最后统一 UI 验收”调整为：

1. 设计冻结
2. UI/UX 原型设计
3. UI 评审冻结
4. 数据库/API 确认
5. 前后端开发
6. 前后端联调
7. UI 还原验收
8. 功能验收
9. 自动进入下一 Sprint

Sprint1 已完成的后端、数据库和用户体系 API 不删除；但后续涉及新业务页面的前端开发必须先走 UI Gate。

## 2. Design System V0.5

### 2.1 品牌颜色

| Token | 色值 | 用途 |
| --- | --- | --- |
| Ocean Primary | `#1890FF` | 主按钮、选中态、重点操作 |
| Deep Sea | `#005B96` | 导航、标题、后台侧栏、关键区块 |
| Pearl White | `#F8FAFC` | 页面背景 |
| Seafood Gold | `#F5A623` | 活动、价格、优惠、会员权益 |
| Success | `#10B981` | 成功、已完成、库存正常 |
| Warning | `#F97316` | 待处理、库存预警、金额强调 |
| Error | `#EF4444` | 异常、失败、未读红点 |

禁止出现未定义紫色作为主视觉色。

### 2.2 字体与密度

- 中文字体：PingFang SC / Microsoft YaHei / system fallback
- 小程序：高密度信息卡片，价格与店铺信息紧贴商品
- PC/iPad 后台：表格优先，筛选区、操作区、分页、Drawer/Form 统一
- 手机 H5 工作台：大按钮 + 卡片 + 状态 + 快捷操作，不复用 PC 复杂表格

### 2.3 公共组件清单

Button、Input、Select、Checkbox、Radio、Switch、Card、Modal、Drawer、Table、Tabs、Badge、Tag、Toast、Loading、Empty、Skeleton、Pagination、StatusDot、PriceText、ProductCard、TaskCard、MetricCard。

- USER-001 后端、Migration、API 保留。

## 10. 新 Sprint1-Sprint13 执行顺序

每个 Sprint 统一采用：

1. `SPRINT-X-UI-001` 页面需求读取
2. `SPRINT-X-UI-002` 页面原型设计
3. `SPRINT-X-UI-003` 状态/交互设计
4. `SPRINT-X-UI-GATE` UI 冻结
5. `SPRINT-X-DB` 数据库开发
6. `SPRINT-X-API` 后端开发
7. `SPRINT-X-FE` 前端开发
8. `SPRINT-X-INTEGRATION` 联调
9. `SPRINT-X-UI-QA` UI 还原验收
10. `SPRINT-X-FUNCTION-QA` 功能验收
11. `SPRINT-X-REPORT` Sprint 总结

Sprint13 调整为全系统集成测试与最终验收，不再作为首次 UI 验收阶段。

## 12. 结论

UI-Sprint0.5 已建立初版全局 UI 原型与设计系统，但不得视为最终冻结版本。下一步应由产品负责人进行第一次全局 UI 评审，通过后再继续正式业务页面开发。
