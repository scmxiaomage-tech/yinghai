## R6 支付中心

- `payments.order_id -> orders.id`：订单与支付单一对多。
- `payments.user_id -> users.id`：支付单归属用户。
- `payment_events.payment_id -> payments.id`：支付事件归属支付单，允许通知解析前为空。
- `payments.amount` 必须来自 `orders.payable_amount`，客户端不得提交。
- 支付成功必须校验渠道金额、支付单金额、订单应付金额三者一致。
- 支付成功后订单状态更新为 `PAID`。
- 支付成功库存扣减写入 `inventory_transactions`，幂等键为 `sku_id + reference_type + reference_id + type`，其中 `reference_type=ORDER`、`reference_id=order_no`、`type=DEDUCT`。
- `payment_events(provider, provider_event_id)` 用于渠道通知幂等审计。

- R4 购物车阶段禁止调用库存锁定、释放、扣减能力；只保存购买意向，库存校验在订单阶段执行。

- R5 订单创建事务包含 orders、order_items、库存 LOCK、库存流水，取消/超时关闭事务包含订单状态更新与库存 UNLOCK。

## R7 退款中心

- `refunds.order_id -> orders.id`：退款单归属订单；R7 使用 `refunds.order_id` 唯一约束，一个订单只允许一张整单全额退款单。
- `refunds.payment_id -> payments.id`：退款单关联原成功支付单；退款金额必须满足 `refund.amount = payment.amount = order.payable_amount`。
- `refunds.user_id -> users.id`：退款单归属用户，用户端只能查看自己的退款单。
- `refund_events.refund_id -> refunds.id`：退款事件归属退款单；渠道通知在解析前允许为空。
- `refund_events(provider, provider_event_id)`：渠道退款通知幂等审计键。
- 退款成功状态流：`orders.PAID -> orders.REFUNDING -> orders.REFUNDED`。
- 退款成功库存补偿：通过库存中心写入 `inventory_transactions`，其中 `type=REFUND_RETURN`、`reference_type=REFUND`、`reference_id=refund_no`，禁止直接修改库存数量。
