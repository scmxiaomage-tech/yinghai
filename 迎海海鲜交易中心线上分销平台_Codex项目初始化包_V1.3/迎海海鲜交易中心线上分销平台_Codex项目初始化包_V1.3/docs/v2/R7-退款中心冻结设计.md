# R7 退款中心冻结设计

## 1. R7 范围

R7 只支持已支付订单的整单全额退款，建立可审计、可幂等、可补偿的退款资金链路。

允许能力：

- 创建退款单。
- 调用支付渠道发起退款。
- 接收退款通知。
- 查询退款状态。
- 退款成功后推动订单进入 `REFUNDED`。
- 退款成功后通过库存中心执行 `REFUND_RETURN`。
- 后台只读查询退款单。

## 2. R7 非范围

R7 不开发售后中心、售后审核、退货、换货、退货物流、配送、骑手、佣金、提现、钱包、结算、对账、发票、优惠券退款补偿、运费逆向规则、部分 SKU 售后、多次部分退款、平台仲裁。

## 3. 退款状态机

退款状态：

- `PENDING`
- `PROCESSING`
- `SUCCESS`
- `FAILED`
- `CLOSED`

正常流转：

```text
PENDING -> PROCESSING -> SUCCESS
```

失败流转：

```text
PENDING -> FAILED
PROCESSING -> FAILED
```

`SUCCESS` 是终态，不允许再改为其他状态。

## 4. 订单状态增量

R7 对 R5/R6 订单状态机做增量补充：

```text
PAID -> REFUNDING -> REFUNDED
```

不得由前端直接修改订单状态，必须由退款服务在渠道确认成功后推动。

## 5. payment 与 refund 关系

- `orders 1:N payments`
- `orders 1:1 refunds`，R7 第一版一个订单只允许一个退款单。
- `payments 1:N refunds` 在模型上预留，但 R7 第一版通过 `refunds.order_id` 唯一约束限制整单全额退款。

金额规则：

```text
refund.amount = payment.amount = order.payable_amount
```

任何不一致必须拒绝退款并记录审计事件。

## 6. 库存补偿规则

支付成功时库存已经 `DEDUCT`，退款成功后通过库存中心执行：

```text
REFUND_RETURN
```

禁止直接 `stock = stock + quantity`。

库存幂等键：

```text
sku_id + reference_type + reference_id + type
```

R7 使用：

- `reference_type = REFUND`
- `reference_id = refund_no`
- `type = REFUND_RETURN`

## 7. 事务边界与锁顺序

创建退款：

1. 锁订单。
2. 锁成功支付单。
3. 校验订单 `PAID`。
4. 校验支付单 `SUCCESS`。
5. 校验金额一致。
6. 创建退款单。
7. 订单进入 `REFUNDING`。
8. 写入 `REFUND_CREATED`。
9. 调用 Provider。
10. 更新退款单为 `PROCESSING` 或失败。

退款成功处理：

1. 锁退款单。
2. 锁支付单。
3. 锁订单。
4. 校验金额。
5. `refund -> SUCCESS`。
6. `order -> REFUNDED`。
7. 执行库存 `REFUND_RETURN`。
8. 写入 `refund_events`。

## 8. 幂等策略

- `refunds.order_id` 唯一，防止并发创建多张退款单。
- 渠道事件使用 `refund_events(provider, provider_event_id)` 审计。
- 库存补偿使用库存流水唯一键。
- 重复通知不得重复改订单、重复恢复库存。

## 9. Provider

R7 新增 `RefundProvider`：

- `CreateRefund`
- `QueryRefund`
- `VerifyRefundNotification`

实现：

- `WechatRefundProvider`：微信退款边界，真实配置缺失时返回 `REFUND_CONFIG_MISSING`。
- `MockRefundProvider`：仅 dev/test 使用，生产环境禁止。

## 10. API

用户端：

- `GET /api/v2/app/refunds/:id`
- `GET /api/v2/app/orders/:id/refund`

后台：

- `GET /api/v2/admin/refunds`
- `GET /api/v2/admin/refunds/:id`
- `POST /api/v2/admin/orders/:id/refund`

渠道通知：

- `POST /api/v2/refunds/wechat/notify`
- `POST /api/v2/refunds/mock/notify`

## 11. 错误码

- `REFUND_NOT_FOUND`
- `REFUND_ALREADY_EXISTS`
- `REFUND_NOT_ALLOWED`
- `REFUND_AMOUNT_MISMATCH`
- `REFUND_PROVIDER_ERROR`
- `REFUND_ALREADY_SUCCESS`
- `REFUND_INVALID_STATE`
- `REFUND_NOTIFICATION_INVALID`
- `REFUND_SIGNATURE_INVALID`
- `REFUND_CONFIG_MISSING`

## 12. 后续 R8 边界

售后申请、退货、换货、物流、佣金、钱包、提现、结算、对账等全部留到后续阶段，不在 R7 实现。
