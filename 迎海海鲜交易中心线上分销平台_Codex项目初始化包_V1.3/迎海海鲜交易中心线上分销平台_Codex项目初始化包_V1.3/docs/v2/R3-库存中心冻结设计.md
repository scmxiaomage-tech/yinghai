# R3 库存中心冻结设计

## 目标与边界

R3 只建设 SKU 维度库存基础设施，不进入购物车、订单、支付、退款、分销、结算。

库存最小管理单位为 SKU，禁止以 Product 作为扣减单位。

## 数据表

### inventories

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT UNSIGNED PK | 主键 |
| sku_id | BIGINT UNSIGNED UNIQUE | SKU，一条 SKU 只能有一条库存 |
| total_stock | INT UNSIGNED | 总库存 |
| locked_stock | INT UNSIGNED | 已锁库存 |
| sold_stock | INT UNSIGNED | 已售库存 |
| warning_stock | INT UNSIGNED | 预警库存 |
| version | BIGINT UNSIGNED | 乐观版本预留 |
| created_at | DATETIME(3) | 创建时间 |
| updated_at | DATETIME(3) | 更新时间 |

`available_stock` 不物理存储，统一动态计算：

`available_stock = total_stock - locked_stock`

原因：避免三字段冗余导致不一致；列表查询通过 SQL 表达式计算，性能由 `sku_id` 唯一索引与后续必要索引保障。

### inventory_transactions

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT UNSIGNED PK | 主键 |
| sku_id | BIGINT UNSIGNED | SKU |
| type | VARCHAR(16) | INCREASE / DECREASE / LOCK / UNLOCK / DEDUCT |
| quantity | INT UNSIGNED | 变更数量 |
| before_stock | INT UNSIGNED | 变更前 total_stock |
| after_stock | INT UNSIGNED | 变更后 total_stock |
| before_locked_stock | INT UNSIGNED | 变更前 locked_stock |
| after_locked_stock | INT UNSIGNED | 变更后 locked_stock |
| reference_type | VARCHAR(32) NULL | 幂等业务来源类型 |
| reference_id | VARCHAR(64) NULL | 幂等业务来源 ID |
| remark | VARCHAR(255) NULL | 备注 |
| operator_type | VARCHAR(32) | admin / system / app |
| operator_id | VARCHAR(64) NULL | 操作人 |
| created_at | DATETIME(3) | 创建时间 |

唯一约束：

`uk_inventory_transactions_reference(reference_type, reference_id, type)`

用于 LOCK / UNLOCK / DEDUCT 幂等保护。人工调整如无 reference，可由服务层生成 reference。

## 状态

SKU 库存状态：

- `IN_STOCK`：`total_stock - locked_stock > warning_stock`
- `LOW_STOCK`：`0 < total_stock - locked_stock <= warning_stock`
- `OUT_OF_STOCK`：`total_stock - locked_stock <= 0`

用户端允许返回 `availableStock` 与 `stockStatus`；后台返回完整库存。

## 并发方案

采用 MySQL 事务 + 原子条件 UPDATE。

锁库：

```sql
UPDATE inventories
SET locked_stock = locked_stock + ?, version = version + 1
WHERE sku_id = ?
AND total_stock - locked_stock >= ?;
```

扣减：

```sql
UPDATE inventories
SET total_stock = total_stock - ?, locked_stock = locked_stock - ?, sold_stock = sold_stock + ?, version = version + 1
WHERE sku_id = ?
AND locked_stock >= ?
AND total_stock >= ?;
```

释放：

```sql
UPDATE inventories
SET locked_stock = locked_stock - ?, version = version + 1
WHERE sku_id = ?
AND locked_stock >= ?;
```

所有库存变更必须在同一事务中写入 `inventory_transactions`。

## 操作规则

- `INCREASE`：后台补货、初始导入、采购入库。
- `DECREASE`：后台人工减少库存，不用于订单销售。
- `LOCK`：创建订单时锁库存，不扣 `total_stock`。
- `UNLOCK`：订单取消、超时未支付、支付失败释放库存。
- `DEDUCT`：支付成功后同时减少 `total_stock` 与 `locked_stock`。

## Service 边界

库存 Service 必须提供：

- `GetInventory`
- `ListInventories`
- `AdjustInventory`
- `LockInventory`
- `UnlockInventory`
- `DeductInventory`
- `ListTransactions`

后续 R4/R5 订单模块直接调用 Service，不通过 HTTP 反调。

## API

用户端：

- `GET /api/v2/app/products/:id`：商品详情 SKU 增加库存字段。

后台：

- `GET /api/v2/admin/inventories`
- `GET /api/v2/admin/inventories/:skuId`
- `POST /api/v2/admin/inventories/:skuId/adjust`
- `GET /api/v2/admin/inventory-transactions`
